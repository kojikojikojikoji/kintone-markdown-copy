# kintone-markdown-copy

English version: [README.md](./README.md)

kintone のレコードや一覧を、Markdown 表・Markdown 箇条書き・TSV のいずれかの形式でクリップボードにコピーするプラグイン。Slack・Notion・GitHub・表計算ソフトへ、フィールドを 1 つずつ整形し直さずに貼り付けられる。

レコード詳細画面と一覧画面のヘッダーに「コピー」ボタンが付く。クリックして形式を選べばクリップボードに入る。処理はすべてブラウザと kintone REST API の中で完結し、外部サーバーへは一切通信しない。

## 機能

- 3 形式（`Markdown表`・`Markdown箇条書き`・TSV）のドロップダウン付きコピーボタンを追加する。
- 詳細画面では `event.record` に表示中のフィールド値をコピーする。
- 一覧画面では、現在の絞り込み・ソート条件に一致するレコードを上限件数まで取得し、行として出力する。
- 管理者はプロファイルを最大 10 件定義できる。プロファイルは、出力フィールドとその順序、対象画面、日時フォーマットや空値の表記といった形式オプションの組。
- 各フィールドを型別の規則（後述）でテキスト化し、選択した形式に応じてエスケープする。

## 対応画面

| 画面 | デスクトップ | モバイル |
|---|---|---|
| レコード詳細 | 対応 | 対応 |
| レコード一覧（`list`・`custom` ビュー） | 対応 | 非対応 |
| カレンダービュー | ボタン非表示 | ボタン非表示 |

モバイルの一覧画面には対応しない。モバイルブラウザはユーザー操作と同じジェスチャー内でしかクリップボード書き込みを許可せず、一覧コピーは先にレコード取得が入るため、どのブラウザでも 2 段階の確認操作が必要になる。詳細は「制限事項」を参照。

## フィールド型ごとの変換

エスケープの前に、各フィールドを次の規則でテキスト化する。

- 文字列（1 行・複数行）: 値をそのまま。
- リッチエディター: 簡易な HTML→Markdown 変換。対応タグは `strong`/`b`、`em`/`i`、`a`、`ul`/`ol`/`li`、`br`、`p`/`div`、`img`（alt テキスト）。それ以外のタグは除去し、テキストだけを残す。
- 数値・計算（数値）: 値そのまま。桁区切りはオプションで付けられる。フィールドの単位記号は付けない。
- 日付・時刻・日時・作成日時・更新日時: プロファイルの日時オプションに従って整形する。日時はログインユーザーのタイムゾーンに変換する。
- ドロップダウン・ラジオボタン・チェックボックス・複数選択・カテゴリー: 選択値をカンマ区切りで連結。
- ユーザー選択・組織選択・グループ選択・作業者・作成者・更新者: 表示名。
- リンク: 値をそのまま（`[text](url)` 形式にはしない）。
- 添付ファイル: ファイル名をカンマ区切りで連結。ファイル本体はコピーしない。
- テーブル: 詳細画面では本文の後に独立したブロックとして出力する。一覧画面では `(N行)` と出力する。

## 形式ごとの貼り付け先

- Markdown 表: Notion・GitHub など、表を描画できる Markdown エディタ向け。
- Markdown 箇条書き: Slack・Notion・GitHub 向け。Slack は Markdown の表を描画しないので、Slack にはこちらを使う。
- TSV: Excel・Google スプレッドシートなどの表計算ソフト向け。桁区切りをオフにしておくと、数値は数値として貼り付く。

## インストール

1. プラグインの zip をビルドする。
   ```
   npm install
   npm run build
   npm run pack
   ```
   初回の `pack` で `private.ppk` と `kintone-markdown-copy.zip` が生成される。`private.ppk` を保管しておくと、再ビルドしてもプラグイン ID が変わらない。コミットはしないこと。
2. kintone のアプリ設定からプラグイン画面を開き、`kintone-markdown-copy.zip` をアップロードする。

## 設定

アプリのプラグイン一覧からプラグイン設定を開く。

1. プロファイルを 1 件以上作成する。プロファイルごとに名前、対象画面（詳細・一覧・両方）、出力するフィールドとその順序を設定する。
2. 日時フォーマット、桁区切り、空値の表記をプロファイルごとに設定する。
3. 一覧コピーの「上限件数」を 1〜5000 の範囲で設定する。既定値は 500。
4. 既定のプロファイルを選ぶ。

プロファイルには最低 1 つのフィールドが、アプリには最低 1 つのプロファイルが必要。保存済みのフィールドが後からフォームから削除された場合は、設定画面が保存時にフィールドコード付きで知らせる。

## ローカルストレージ

最後に選んだプロファイルと形式を、`localStorage` のキー `kp-mdcopy-<domain>-<appId>-<userCode>` に保存する。次回表示時にドロップダウンの選択状態を復元するためのもので、レコードのデータは含まない。消したい場合は、ブラウザのストレージから kintone ドメインの該当キーを削除する。

## 制限事項

- モバイルの一覧コピーには対応しない（「対応画面」を参照）。
- クリップボードに書き込むのは `text/plain` のみ。`text/html` は書き込まない。
- Slack は Markdown の表を描画しない。Slack には箇条書きか TSV を使う。
- 関連レコード一覧・ラベル・罫線・スペース・グループは出力しない。
- 添付ファイルと画像は本体をコピーせず、ファイル名だけを出力する。
- リッチエディターの変換対象は前述のタグのみ。リッチエディター内の表・見出し・文字色は再現しない。
- 一覧コピーが出力するのはプロファイルのフィールドであり、ビューに表示されている列ではない。

## 開発

```
npm install
npm run typecheck   # tsc --noEmit
npm run test        # vitest (core logic)
npm run build       # dist/desktop.js, dist/mobile.js, dist/config.js
npm run lint        # eslint
npm run pack        # build then package into a plugin zip
```

`test/e2e` の Playwright スペックは、接続先を環境変数（`KINTONE_BASE_URL`、`KINTONE_USERNAME`、`KINTONE_PASSWORD`、`KINTONE_APP_ID`）から読む。CI では実行しない。
